# Packages: `package.toml` and `package.lock`

`dmr install` reads `package.toml` in the current directory, downloads the
dependencies into `./lib` (the default library directory of Drax) and writes
`package.lock`. Use `dmr -C <dir> ...` to run it for another directory.

## Creating a package.toml

`dmr init` writes a default `package.toml` in the current directory. The package
name is the name of the directory (characters other than letters, digits, `_`
and `-` become `_`). It never overwrites an existing file.

```sh
mkdir my_service && cd my_service
dmr init
```

```toml
[package]
name = "my_service"
version = "0.1.0"

[dependencies]
# json = { git = "https://github.com/user/drax-json", tag = "v1.0.0" }
# utils = { path = "../utils" }
```

`dmr install` takes no arguments: it installs what the `[dependencies]` section
lists. To add a package, add a line to that section and run `dmr install`.

## Adding a dependency

`dmr add` writes the line in `[dependencies]` for you (it keeps the rest of the
file as it is):

```sh
dmr add drax-lang/griht              # GitHub: https://github.com/drax-lang/griht
dmr add drax-lang/griht@v1.0.0       # the tag v1.0.0
dmr add https://example.com/x/y.git --branch main
dmr add git@github.com:user/repo.git --rev 3f2a1c9
dmr add ../utils                     # a local path
dmr add drax-lang/griht --name g     # another name in lib/
```

`dmr install <spec>` takes the same arguments: it adds the dependency and then
installs.

| Option | |
|--------|---|
| `--tag t`, `--branch b`, `--rev r` | which version to use (at most one; `@ref` after `user/repo` is a tag) |
| `--name n` | the name under `lib/` (default: the repository or directory name, without `.git`) |

A dependency that is already in the file is an error, and so is a name that
is not valid (see the rules below). The package is not downloaded by `add`:
run `dmr install`.

## package.toml

```toml
[package]
name = "meu_servico"
version = "0.1.0"

[dependencies]
# 1. official registry (there is no central server yet: not supported)
json = "1.2.0"

# 2. GitHub / any git url, with a tag, a branch or a commit
http = { git = "https://github.com/usuario/drax-http", tag = "v0.4.1" }

# 3. own server (registry or tarball): not supported yet
auth_corp = { registry = "https://pkg.minhaempresa.com", version = "2.1.0" }

# 4. local path, for developing packages in parallel
core_utils = { path = "../core_utils" }
```

A small TOML subset is accepted: `[package]`, `[dependencies]`, comments (`#`),
strings (`"..."` or `'...'`) and one-line inline tables.

| Form | Status |
|------|--------|
| `name = "1.2.0"` | recognized, **not supported yet**: install reports an error |
| `{ git = url }` | supported. At most one of `tag`, `branch`, `rev`; none means the default branch (`HEAD`) |
| `{ registry = url, version = x }` | recognized, **not supported yet** |
| `{ path = "dir" }` | supported: `lib/<name>` is a symlink to the directory, edits are seen at once |

Rules:

- A dependency name becomes the directory `lib/<name>`: letters, digits, `_`
  and `-` only (at most 64, no leading `-`).
- A dependency needs exactly one source (`git`, `registry` or `path`).
- A relative `path` is relative to the `package.toml` that declares it. For a
  git package, that is inside the downloaded repository.

## How a package is used

```
import('http')          # lib/http.dx, or lib/http/main.dx for a package
import('http/client')   # lib/http/client.dx
```

A package is a directory with a `main.dx` (its entry) and, optionally, its own
`package.toml`. See `docs/imports.md` of the interpreter for the resolution
rules.

## install

1. Parses `package.toml` and `package.lock`.
2. Resolves the dependencies breadth first. The dependencies of a dependency
   (its own `package.toml`) are installed too, **flat** in the same `lib/`.
   The same name from two different sources is a conflict (error).
3. **git**: keeps a bare clone per url in the cache (`$DMR_CACHE`, else
   `$XDG_CACHE_HOME/dmr`, else `~/.cache/dmr`), fetches it once per run,
   resolves the tag/branch/rev to a full commit and extracts that commit with
   `git archive` into `lib/<name>`. There is no `.git` inside `lib/`.
4. Writes `lib/<name>/.dmr-rev` (the commit), so an unchanged package is not
   downloaded or extracted again.
5. Removes the packages that dmr installed before and that are not used
   anymore.
6. Writes `package.lock` (only when everything worked).

With a lock, `install` uses the locked commit when the dependency (source and
requested ref) did not change, even if the tag or the branch moved.
`dmr update` ignores the lock and resolves tags and branches again.

dmr never touches what it did not install: if `lib/<name>` already exists and
is not managed by dmr, install stops with an error. Your own modules
(`lib/mine.dx`) are never removed.

## package.lock

Generated, sorted by name, no timestamps: commit it and do not edit it.

```toml
# This file is generated by dmr. Do not edit it.
version = 1

[[package]]
name = "http"
source = "git+https://github.com/usuario/drax-http"
requested = "tag:v0.4.1"        # tag:x | branch:x | rev:x | head
rev = "0123456789abcdef0123456789abcdef01234567"
dependencies = ["json"]

[[package]]
name = "core_utils"
source = "path+../core_utils"
```

`lib/` and the cache are build outputs: add `lib/` to your `.gitignore` when
it only holds downloaded packages (or keep your own modules elsewhere).

## Security

`package.toml` is untrusted input (it can come from a dependency).

- git, tar and every other program are started **without a shell**, with an
  argument list, so no value is interpreted by a shell.
- Names are checked before they become paths, and urls, tags, branches and
  commits cannot start with `-` (no option injection into git).
- Only directories directly inside `lib/` are removed, and only when dmr
  installed them. A symlink is unlinked, its target is never touched. Names
  read from `package.lock` are checked too.
- dmr sets `GIT_TERMINAL_PROMPT=0`: it never waits for a password, a
  repository that needs credentials fails (configured credential helpers or
  ssh keys still work).
- Downloading code is executing trust: a package is Drax code that you will
  import. Pin `rev` or use the lock for what you do not control.

## Limits

- Registry (`name = "1.2.0"`, `registry = ...`) is not implemented.
- No version solving: git dependencies are exact (a tag, a branch or a commit).
- Only branches and tags are fetched: a `rev` must be reachable from one of them.
- One directory per name: two versions of the same package can not coexist.
- POSIX only (`fork`, `symlink`, `git` and `tar` in the PATH).
